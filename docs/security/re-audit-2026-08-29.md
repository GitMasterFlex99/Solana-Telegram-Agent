# Security re-audit — 2026-08-29

## Findings requiring remediation before mainnet

- Replace the single global Telegram chat allowlist with per-user authorization and short-lived action/session binding.
- Add bounded per-user and global rate limits.
- Add CI gates for dependency audit, secret scanning, static analysis, and lockfile integrity.
- Add CSP/security-header tests for the web app.
- Cryptographically bind each transaction intent to the connected wallet, intended action, expiry, and server-side policy decision.
- Revalidate the wallet and transaction immediately before signing.
- Add replay/stale-intent tests.
- Validate on-chain account types and expected program IDs before signing.
- Add adversarial token/program fixtures and malicious metadata tests.
- Ensure BYOK AI keys are never persisted unless a dedicated secrets service is used; prefer direct provider calls where practical.

## Positive controls verified from current source

- Private keys and seed phrases are prohibited by design.
- Dedicated trading-wallet warning is documented and shown before wallet connection.
- Mainnet trading is currently disabled.
- AI/social content is not permitted to authorize transactions.
- Transaction release gate requires simulation and explicit user approval.
- External market-data failures fail closed at the user-facing operation.
- The frontend uses the current Solana Kit/Wallet Standard direction.

## Security standard

Baseline: OWASP ASVS 5.0 Level 2, with selected stronger controls for wallet, secrets, and transaction authorization. This is an engineering target, not a certification or independent penetration-test result.

## Release rule

Do not enable mainnet transaction execution until every remediation item above has an implementation and automated/manual test evidence.
