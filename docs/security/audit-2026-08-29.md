# Security re-audit — 2026-08-29

## Scope
Reviewed the Telegram authorization path, market-data fetch path, BYOK AI boundary, wallet safety requirements, transaction release gate, and threat model.

## Findings and changes

### Fixed: Telegram abuse controls
- Added per-chat rate limiting for bot actions.
- Callback handlers now authorize and rate-limit before performing the requested action.
- Unauthorized callbacks do not reach business logic.

### Fixed: external fetch timeout
- DexScreener requests now have an 8-second abort timeout.
- Upstream errors are returned to users as generic failures; internal error details are not sent to Telegram.
- Market responses are type-checked at the boundary and only Solana pairs above the liquidity filter proceed.

### Fixed: AI resource and prompt-injection boundary
- BYOK AI input is capped at 50 KB.
- AI requests have a 15-second timeout.
- Market/social data is explicitly treated as untrusted data, not instructions.
- Provider errors are intentionally generic.
- AI output is bounded before it can be passed to UI layers.
- AI remains advisory and cannot authorize a transaction.

## Remaining high-priority controls

1. Replace the single-chat environment allowlist with a proper user/session authorization model before public deployment.
2. Add distributed rate limiting if more than one bot instance is deployed.
3. Add automated secret scanning, dependency audit, SAST and lockfile verification in CI.
4. Add security headers/CSP tests for the mobile web app.
5. Add transaction-policy unit tests, replay/staleness tests and adversarial token fixtures.
6. Add wallet-identity binding and server-side revalidation before any mainnet transaction.
7. Add address classification before SOL or token transfers. Solana's official guidance requires classifying the recipient account rather than trusting an address string.
8. Keep mainnet signing disabled until the entire release gate passes.

## Reference baseline

OWASP ASVS 5.0 Level 2 is the baseline, with selected Level 3 controls for transaction authorization and sensitive secrets. Security logging must record useful metadata without recording credentials or other sensitive values. Production must contain only required functionality, with development/test functionality isolated from the production environment.

## Release decision

**Mainnet trading: BLOCKED.**

This audit improves the non-trading surfaces but does not constitute a penetration test or independent security assessment. A production release still requires automated and manual testing of the complete transaction path.
