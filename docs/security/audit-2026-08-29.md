# Security audit — 2026-08-29

## Scope

Reviewed the Telegram authorization path, market-data fetch path, BYOK AI boundary, wallet safety requirements, transaction-intent controls, CI security gates, and the mainnet release boundary.

## Verified controls

### Telegram abuse controls

- Access fails closed unless `TELEGRAM_ALLOWED_USER_IDS` is configured.
- Authorization checks both the Telegram user and optional chat restriction.
- Callback handlers authorize and rate-limit before business logic runs.
- Rate limiting is keyed by user/chat pair.

### External market-data boundary

- DexScreener requests have an 8-second abort timeout.
- Upstream failures are returned as generic user-facing failures.
- Market responses are checked at the application boundary.
- Only Solana pairs above the configured liquidity filter proceed to the scanner.

### AI resource and prompt-injection boundary

- BYOK AI input is capped at 50 KB.
- AI requests have a 15-second timeout.
- Market/social data is treated as untrusted data, not instructions.
- Provider errors are intentionally generic.
- AI output is bounded before it reaches UI layers.
- AI is advisory and cannot authorize a transaction.

### Wallet and transaction boundary

- Private keys and seed phrases are prohibited by design.
- A dedicated trading-wallet warning is required before connection.
- Mainnet trading is currently disabled.
- Transaction intent is wallet-bound and expires quickly.
- Transaction policy limits slippage and requires an approved program set.
- AI, social content, Telegram callbacks, and URL input cannot authorize a transaction or provide arbitrary transaction bytes.
- Simulation and explicit user approval remain required before any future signing flow.

### CI controls

- TypeScript typechecking runs in CI.
- The mobile web production build runs in CI.
- Tests run in CI.
- High-severity dependency auditing runs in CI.
- Gitleaks secret scanning runs in CI.
- CI installs dependencies from a generated lockfile and uses `npm ci` for the resolved tree.

## Remaining high-priority controls

1. Commit a repository lockfile so dependency resolution is reproducible without generating a new lockfile during CI.
2. Add distributed rate limiting if more than one bot instance is deployed.
3. Add CSP/security-header tests for the mobile web app.
4. Cryptographically bind each future transaction intent to the connected wallet, intended action, expiry, and server-side policy decision.
5. Revalidate the wallet and transaction immediately before signing.
6. Add replay/stale-intent tests around the complete transaction path.
7. Validate on-chain account types and expected program IDs before signing.
8. Add adversarial token/program fixtures and malicious metadata tests.
9. Ensure BYOK AI keys are never persisted unless a dedicated secrets service is used; prefer direct provider calls where practical.
10. Keep mainnet signing disabled until the complete release gate has implementation and automated/manual test evidence.

## Security standard

Baseline: OWASP ASVS 5.0 Level 2, with selected stronger controls for wallet, secrets, and transaction authorization. This is an engineering target, not a certification or independent penetration-test result.

## Release decision

**Mainnet trading: BLOCKED.**

The current repository is suitable for the read-only research/scanning surface, but the transaction path is not ready for production execution. Do not weaken the release gate to enable mainnet trading.
